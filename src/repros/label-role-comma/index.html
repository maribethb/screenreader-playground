Screenreaders disagree about pausing between the label and the role

Screenreaders don't agree on whether to put a comma between an element's label and its role. VoiceOver adds one. NVDA doesn't, so the end of the label runs straight into the role. You can't write one label that reads well in both.

Affected

"Yes" means the screenreader adds its own comma between the label and the role.

Steps to reproduce

  1. Press Tab to move focus to the element under the "Repro" heading.
  2. Listen to how the label and the role are joined.

Expected output

Every screenreader joins the label and the role the same way, so the same label works everywhere.

Actual output

With the no-comma variant:

  • VoiceOver: "Lunch plans, from Sam, has attachment, email"
  • NVDA: "Lunch plans, from Sam, has attachment email"

NVDA's version sounds like the item has an email attached.

Variants

  • no-comma: the label ends without punctuation. This is the broken version.
  • trailing-comma: the label ends with a comma, so NVDA pauses too. This is the workaround Blockly uses, on non-Apple devices only.

Repro

Notes

  • This isn't a spec problem. Nothing says how a screenreader should join the label and the role, and both behaviors are reasonable on their own. Maybe the spec should pick one, so that screenreaders are consistent. Either choice would be fine, as long as they all make the same one.
  • A page can't tell which screenreader is running. If you only want the comma for NVDA, the closest you can get is leaving it out on Apple devices, since that's the only place VoiceOver runs.

Sources

  • Blockly issue 10185 (July 2026): block labels no longer ended in a comma, so NVDA ran the label into the role and VoiceOver didn't.
  • Blockly pull request 10279 (August 2026): the workaround, which adds a trailing comma to labels except on Apple devices.
  • NVDA's speech.py: NVDA joins separate pieces of speech, like the label and the role, with two spaces. The comment says that's for chunks that "should be spoken without pauses".
  • VS Code issue 96046 (2020): VS Code switched to commas between the parts of its aria-labels, because Apple's platforms use commas there and screenreaders slow down at them.
  • What working on GOV.UK navigation taught us about accessibility (GOV.UK, 2017): of the punctuation they tried for a hidden pause, the comma paused in every screenreader they tested.
