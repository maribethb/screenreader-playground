Repeated and overlapping live region announcements

Affected

Steps to reproduce

  1. Jump to the "Repro" heading.
  2. Move to the "Add block" button.
  3. Press the button three times in quick succession.

Expected output

The ARIA spec doesn't say what should happen when a live region is set to the same text twice, so this is what would be reasonable rather than what the spec requires: "Block added" is announced once per press.

Actual output

"Block added" is announced once, after the first press. Later presses set the same text, which isn't a change, so nothing is announced.

Variants

  • naive: sets the live region's text on every press. This is the broken version.
  • debounce: clears the region on every press, then sets the text once presses stop.
  • queue: queues every message and announces them one at a time, clearing the region in between.

Notes

  • This is a placeholder repro, written to try out the site's structure. The steps, outputs and variants haven't been checked against a real screenreader or against the Blockly workaround history.
  • None of the variants stop announcements from overlapping with the screenreader's own output, like reading the newly focused element. That might end up as its own repro.
