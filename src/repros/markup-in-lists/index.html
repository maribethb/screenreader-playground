Markup inside list items

VoiceOver on macOS has several quirks when it announces lists with other markup inside the list items. Announcements are inconsistent between forward and backward navigation, and there are more stops than expected.

Affected

Steps to reproduce

  1. Navigate to the list under the "Repro" heading. The list has four items: plain text, a paragraph, a heading and a button.
  2. Navigate through the list items one at a time (VO+Right Arrow in VoiceOver, Down Arrow in NVDA and JAWS).
  3. Navigate backward through the list items one at a time (VO+Left Arrow in VoiceOver, Up Arrow in NVDA and JAWS).
  4. Compare the output of forward vs backward navigation.

Expected output

Navigating through a list of 4 items would take 4 navigation stops, and the announcements would be the same in either direction.

Actual output

VoiceOver forward navigation:

  1. Bullet, This is plain text, 1 of 4
  2. Bullet, 2 of 4
  3. This is a paragraph
  4. Bullet, 3 of 4
  5. Heading, This is a heading
  6. Bullet, 4 of 4
  7. Button, This is a button

VoiceOver backward navigation:

  1. Button, This is a button, 4 of 4
  2. Bullet
  3. Heading, This is a heading, 3 of 4
  4. Bullet
  5. This is a paragraph, 2 of 4
  6. Bullet
  7. Bullet, This is plain text, 1 of 4

Whether or not the position in the list is announced depends on the direction of navigation, and stopping on "Bullet" for each item is distracting. You might think you could get around that by hiding the bullets, but that's complicated by Safari hiding list semantics from VoiceOver if you hide the list decorations.

Repro

Notes

  • This isn't a spec problem, just an implementation quirk of VoiceOver.

Sources

  • Blockly issue 9618 (March 2026): users expected H to move between flyout labels, and it didn't, because flyout labels were not true headings. A comment from micro:bit's user testing says users "do tend to try shortcuts they're used to". Exploring this issue led us to discover this unfortunate VoiceOver quirk.
  • Blockly pull request 9874: our workaround, which adds Blockly's own H and Shift+H shortcuts to move between labels in the flyout.
  • Blockly pull request 9774: added ", heading" to the end of the label's aria-label, with the comment explaining why it couldn't use the heading role.
  • Blockly issue 9495: the discussion of the flyout's ARIA structure. It started out proposing role="heading" for labels, and ended up with list items.
